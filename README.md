# 同频 · Listen Together

可自行部署的网易云音乐多人听歌室。房主连接网易云账号后，朋友无需登录网易云，即可加入房间、共同点歌、切歌、调整进度和聊天。

使用 React、TypeScript、Vite、Express、Socket.IO 和 Node 内置 SQLite。

## 快速开始

需要 **Node.js 24.14.0 或更高版本**及 npm，无需额外安装数据库。在项目根目录运行：

```sh
npm ci
npm run dev
```

打开 [http://localhost:5173](http://localhost:5173)：

1. 创建房间，填写房间名称和昵称，可选设置密码。
2. 房主点击「连接网易云」，使用网易云音乐 App 扫码并确认登录；也可手动连接已有 Cookie。
3. 搜索歌曲，或通过「链接点歌」添加网易云歌曲链接、数字 ID、歌单。
4. 点击「邀请朋友」分享房间链接，朋友填写昵称和房间密码后加入。
5. 房主开始播放。每个浏览器首次收听时，需要点击「开启声音」。

开发前端使用 `5173` 端口，后端使用 `3001` 端口。Vite 将 `/api` 和 `/socket.io` 代理至后端；修改后端端口时，也需修改 [Vite 代理配置](client/vite.config.ts)。

### 无账号演示

先停止正在运行的开发服务，再启动演示模式：

```sh
npm run demo
```

创建房间后点击「连接演示音源」，搜索「推荐」或添加歌曲 ID `1`–`6`。演示音频由本地程序合成，可体验房间同步、播放方式、队列和聊天，无需网易云账号。

未设置 `DATA_DIR` 时，真实模式使用 `data/`，演示模式使用 `data/demo/`。如果已经复制 `.env.example`，其中的 `DATA_DIR=./data` 会覆盖这个默认值；切换演示模式时，应将它改为 `./data/demo` 或移除该项。

## 房间功能

| 角色 | 可执行操作 |
| --- | --- |
| 所有成员，含房主 | 搜索、点歌、导入歌单、上一首 / 下一首、选择队列歌曲、调整播放进度、修改播放方式、聊天 |
| 房主额外权限 | 连接或断开网易云账号、控制房间播放 / 暂停、删除当前歌曲以外的队列项、关闭房间 |

切歌会开始播放所选歌曲，调整进度会保留当前播放或暂停状态。这些操作同步至整个房间；音量、静音和「停止收听」只影响本机。

- 可通过链接邀请加入，也可设置房间密码。
- 每位房主最多保留 5 个房间，每个房间最多 50 名成员、200 首歌曲。
- 每次导入歌单前 100 首，自动跳过队列中已有歌曲。
- 支持同步歌词、在线成员、聊天记录及桌面和窄屏布局。
- 后加入成员同步当前进度；断线时暂停本机播放，重连后重新对齐。
- 同一站点的另一个标签开启声音时，旧标签停止本机收听，避免叠加播放。

### 播放方式

在「播放队列」中选择「播放方式」，所有成员均可修改：

| 方式 | 歌曲结束后的行为 |
| --- | --- |
| 顺序播放 | 按队列顺序播放，最后一首结束后暂停 |
| 列表循环 | 按队列顺序播放，最后一首结束后回到第一首 |
| 随机播放 | 每轮打乱队列并依次播放，新一轮避免连续重复同一首 |

修改播放方式保留当前歌曲和进度，设置随房间保存。手动上一首 / 下一首在顺序和循环模式下可跨越列表首尾；随机模式的上一首沿最近播放历史返回。随机顺序及历史不跨服务重启保存。

## 音源与同步

### 网易云直连

服务端使用房主账号解析歌曲播放地址，按房间和歌曲缓存链接及过期时间。成员取得同一房间解析的链接后，由各自浏览器直接从网易云 CDN 下载和缓冲音频。**服务端不下载、缓存或转发真实音频文件。**

默认请求网易云 `exhigh` 音质，目标码率为 **320 kbps**。实际返回音质取决于歌曲音源及房主账号权限；仅能试听或无法播放的歌曲会被拒绝。播放器不对音频转码，也不使用其他平台匹配音源。「本机播放设置」显示网易云接口返回的码率。

获取链接需要有效会话、房间成员身份和当前歌曲匹配。刷新音频会重新解析链接；更换或断开账号、关闭房间时清除链接缓存。网易云 Cookie 留在服务端，成员不会收到房主的登录凭据。

### 固定速度与缓冲

播放器始终以 **1 倍速**播放，容忍 **0.5 秒以内**的同步偏差。偏差超过 0.5 秒并持续 3 秒时，才通过跳转校正，两次自动校正至少间隔 8 秒。主动调整进度、切歌和缓冲恢复时，会对齐房间时间。

服务端统一维护播放状态及切歌时间，客户端通过时钟采样同步。默认预缓冲目标为 30 秒，可在「本机播放设置」中选择 15 / 30 / 60 秒；设置保存在本机浏览器。较长目标可能增加开始播放时的等待，浏览器限制预加载时会允许使用较短缓冲恢复。

移动浏览器在锁屏或后台时可能暂停音频和网络，回到页面后会重新对齐进度。

## 环境配置

按需将 [.env.example](.env.example) 复制为 `.env`。本地开发可使用默认配置；环境变量由服务端读取。

| 变量 | 默认值或要求 |
| --- | --- |
| `MUSIC_PROVIDER` | `netease`；设为 `demo` 使用本地演示音源 |
| `HOST` / `PORT` | `0.0.0.0` / `3001` |
| `DATA_DIR` | 真实模式为 `data/`，演示模式为 `data/demo/`；显式配置优先 |
| `PUBLIC_ORIGIN` | 页面完整来源，含协议及端口；多个来源用逗号分隔。未设置时允许 `http://localhost:5173` 和 `http://127.0.0.1:5173` |
| `CREDENTIAL_KEY` | 随机 32 字节的 base64 编码，用于加密网易云 Cookie；生产环境必填 |
| `SESSION_SECRET` | 至少 32 字符的随机字符串，用于请求校验；生产环境必填 |
| `COOKIE_SECURE` | HTTPS 部署设为 `true`，本地 HTTP 设为 `false`；生产环境默认 `true`，但 `.env.example` 显式设为 `false` |
| `TRUST_PROXY` | 默认 `false`；仅在可信的单层反向代理之后设为 `true` |
| `NODE_ENV` | 公网部署设为 `production`，启用生产配置检查 |

通过局域网地址或公网域名访问时，将 `PUBLIC_ORIGIN` 设置为实际访问来源。

分别运行以下命令，生成 `CREDENTIAL_KEY` 和 `SESSION_SECRET`，将结果填入 `.env`：

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

## 构建与部署

### 本机运行构建版本

```sh
npm run build
npm start
```

Node 服务同时托管网页、REST 和 Socket.IO，默认通过 [http://localhost:3001](http://localhost:3001) 访问。`npm start` 本身不会设置生产环境。

公网部署前，在 `.env` 或运行环境中设置 `NODE_ENV=production`、两个密钥、实际 `PUBLIC_ORIGIN` 和 `COOKIE_SECURE=true`，并通过 HTTPS 提供访问。

### Docker Compose

将 `.env.example` 复制为 `.env`，填入两个密钥和实际 `PUBLIC_ORIGIN`，并将 `COOKIE_SECURE` 改为 `true`。配置完成后运行：

```sh
docker compose up -d --build
```

[Compose 配置](compose.yaml) 自动使用生产模式，将服务映射到 `3001` 端口，数据保存在命名卷 `listen-data`。

使用 HTTPS 反向代理时，将网页、`/api` 和 `/socket.io` 转发至同一实例，保留原始 Host、转发协议头并支持 WebSocket 升级；此时将 `TRUST_PROXY` 设为 `true`。健康检查地址为 `/api/health`。

当前架构使用单个 Node 实例及 SQLite。多实例部署需要共享房间状态、Socket.IO adapter 和统一播放调度。

## 数据与账号

- SQLite 保存房间、成员、队列、播放方式及最近 100 条聊天记录。后端重启后房间保留，播放暂停，等待房主恢复。
- 网易云凭据按房间使用 AES-256-GCM 加密存储，不写入浏览器 localStorage。应用会话使用 `HttpOnly`、`SameSite=Lax` Cookie，写入请求及 WebSocket 校验会话、来源和权限。
- 房主身份绑定浏览器会话。离开页面会保留房间，清除浏览器 Cookie 后无法恢复原房主身份；目前不支持房主转让或跨设备找回。
- 断开账号会删除该房间凭据并暂停播放；关闭房间会删除房间相关数据，并通知在线成员退出。

**备份数据库及对应密钥。** 本地开发未配置密钥时，会在数据目录生成 `secrets.json`；生产环境使用配置中的密钥。迁移前停止服务，备份数据目录（Docker 使用 `listen-data` 卷）及原密钥。丢失或更换凭据加密密钥将无法解密已有登录信息。不要将 `.env`、数据库或密钥提交到 Git。

## 开发与验证

```sh
npm test
npm run build
```

`npm run build` 包含前后端类型检查；也可单独运行 `npm run typecheck`。

测试使用模拟音源和独立 SQLite，不需要真实网易云账号。覆盖房间权限、扫码流程、凭据加密、HTTP / WebSocket 同步、成员切歌与进度控制、三种播放方式、持久化、共享播放链接、缓冲及固定速度校正。

检查真实网易云二维码生成、匿名搜索及普通歌曲播放地址解析：

```sh
npx tsx scripts/check-netease.ts
```

此检查会访问网易云服务，不覆盖实际扫码确认或会员歌曲授权。真实账号与会员歌曲需手动验证，可用性受账号权限、地区及上游接口变化影响。

## 项目结构

```text
client/src/           页面、播放器、缓冲与时钟同步
server/app.ts         REST、Socket.IO、会话及扫码流程
server/rooms.ts       房间、队列、播放方式及统一播放状态
server/music.ts       网易云接口适配与演示音源
server/repository.ts  SQLite 存储及凭据加密
server/config.ts      环境配置与密钥加载
shared/               前后端共享类型及播放时间计算
tests/                单元与集成测试
scripts/              开发启动及网易云接口检查
```

网易云接口使用 [NeteaseCloudMusicApi Enhanced](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced)。
